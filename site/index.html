It already works on local folders, notebooks, local zip archives, and public GitHub repo URLs.

Install path

Install it and audit a demo repo in three commands.

pipx install git+https://github.com/ThomasAquinas14/labcheck.git labcheck demo-repo labcheck scorecard labcheck-demo-repo

The generated fixture is intentionally broken, so the first scorecard shows hidden state, missing inputs, and concrete first fixes without cloning this source repo.

What it catches

High signal

Hidden notebook state

Detects cells that reference names with no visible prior definition, a classic sign that the notebook only works in the original author's live kernel.

High signal

Saved notebook errors

Flags notebooks committed with traceback/error outputs, which is strong evidence they were not saved after a clean rerun.

High signal

Missing input artifacts

Flags datasets and files that the code reads but the repo never actually includes.

Fresh-clone break

Missing globbed inputs

Flags glob(), os.listdir(), and Path.glob() calls that discover inputs from data-like directories missing from the repo.

Determinism

Unsorted file discovery

Flags input discovery via glob(), os.listdir(), and Path.glob() when the workflow does not stabilize ordering with sorted(...).

Data drift

Mutable remote data URLs

Flags branch/latest-style remote inputs in reads or download calls, such as raw GitHub main links, unless the code documents a checksum or stable snapshot.

Integrity gap

Remote artifacts without checksums

Flags stable-looking remote data reads and downloads when the repo does not verify a sha256, checksum, or hash.

Handoff wedge

Remote downloads without timeouts

Flags direct requests, urllib, curl, or wget downloads that can hang forever in CI or reviewer reruns.

Model/data drift

Unpinned Hugging Face artifacts

Flags Hub datasets, models, and downloads used without revision=, so reruns do not silently follow a moving default branch.

Provenance gap

Orphan generated outputs

Flags committed files under `outputs/`, `results/`, `figures/`, and similar folders when no scanned notebook or script visibly writes them.

Fresh-clone break

Missing output directories

Flags save/write calls to outputs/, models/, and checkpoint-style paths when the directory is not present or created first.

Result drift

Timestamped output paths

Flags generated artifact names derived from datetime.now(), date.today(), time.time(), or similar current-time calls.

Data handoff

DVC and Git LFS restore gaps

Detects data-versioning metadata when the README never tells a reviewer to run dvc pull or git lfs pull.

Contributor pain

Loose environment manifests

Checks `requirements.txt`, `pyproject.toml`, and Conda environment files for dependencies that can drift between machines.

Dependency drift

Moving VCS dependency refs

Flags git+, Mercurial, SVN, and Bazaar dependencies that omit a ref or point at branches such as main.

Fresh-clone break

Missing local helper imports

Flags project-local-looking imports such as utils, helpers, or preprocessing when the module is not shared.

Hardware gotcha

Undocumented accelerator requirement

Flags GPU/CUDA-specific code when README or docs never mention the required accelerator stack or CPU fallback.

Container drift

Floating Docker base image

Flags FROM python:latest, untagged images, and branch-style base tags that can rebuild differently later.

Container gap

Dockerfile skips dependency manifest

Flags Python Dockerfiles that copy the repo but never install requirements.txt, pyproject.toml, or Conda environment files.

Notebook drift

Inline notebook installs

Flags %pip install pandas, !pip install torch, and similar notebook installs when packages are not pinned or moved into a manifest.

Machine setup gap

Inline OS package installs

Flags notebook or script cells that hide apt-get install, brew install, apk add, or similar machine-level setup.

ML reproducibility

Seedless sklearn splits

Flags common scikit-learn splitters and randomized estimators when they omit random_state.

Notebook drift

Seedless pandas samples

Flags pandas sample() calls that can select different rows unless random_state is documented.

Data simulation drift

Seedless NumPy Generators

Flags np.random.default_rng() calls without an explicit seed, even when legacy np.random.seed() appears nearby.

ML reproducibility

PyTorch random_split drift

Flags PyTorch random_split calls that omit a seeded generator, making train/validation splits drift.

ML reproducibility

PyTorch DataLoader shuffle drift

Flags shuffled PyTorch DataLoader instances that omit a seeded generator, making batch order and training trajectories drift.

ML reproducibility

PyTorch worker seed drift

Flags multi-worker PyTorch DataLoader instances that omit worker_init_fn, so random transforms can drift across worker processes.

ML reproducibility

TensorFlow randomness drift

Flags TensorFlow random tensor, shuffle, and initializer calls when no visible TensorFlow seed is set.

ML reproducibility

XGBoost estimator drift

Flags XGBoost estimators that omit random_state or seed, a common source of drifting model fits.

ML reproducibility

Optuna sampler drift

Flags Optuna studies and samplers that omit a fixed sampler seed, making hyperparameter search results hard to compare.

ML reproducibility

JAX PRNG key reuse

Flags repeated JAX random draws that reuse the same PRNG key without a visible split, a subtle source of correlated stochastic inputs.

DataFrame drift

Polars sampling drift

Flags visible Polars sample() and shuffle() calls that omit seed.

Contributor pain

README drift

Finds documented commands that point to files that no longer exist, which is one of the fastest ways to lose trust with new users.

CI drift

Floating GitHub Action reference

Flags workflow actions such as owner/action@main or missing refs that can change after the repo is handed off.

CI proof gap

CI without verification

Flags workflows that install dependencies but never run tests, notebooks, labcheck, or a reproduce/check command.

Handoff gap

Missing setup step

Flags READMEs that show a run command while dependency manifests exist, but never tell a reviewer how to install the environment first.

Automation blocker

Interactive rerun prompts

Flags input() and getpass() calls that stop notebooks, CI jobs, or reviewer reruns until a human types into a terminal.

Workflow clarity

Disconnected analysis files

Surfaces workflow nodes that are not visibly connected to any inputs or outputs, making them hard to place in the real experiment pipeline.

Not just findings. A fix order.

Every Markdown and HTML audit now includes a remediation plan that sorts the highest-impact issues first, explains the first evidence, and carries forward the suggested fix. That makes a report easier to send to a lab, founder, or maintainer without asking them to reverse-engineer the priority list.

Readable on large repos

Large notebook corpora can produce hundreds of repeated findings. Human-readable reports show the first 100 detailed findings by default, include a clear truncation note, and keep JSON/SARIF complete for automation. Use --max-findings all when you need every detail.

Why this is public-hosting safe

Most of your strongest projects rely on paid APIs, which makes public deployment risky. labcheck was chosen to invert that constraint:

- deterministic checks - local-first CLI - static sample audits - no LLM runtime dependency - no wallet-drain surface - easy to host on GitHub Pages / Netlify / Oracle static hosting

Try the browser demo

The static demo page can quick-scan a single notebook, a small set of local repo files, or bounded public GitHub repo files entirely in the browser. No upload, no backend, no inference key, no bill. The privacy and safety model explains the exact boundaries.

It includes a visual lineage panel, rough manifest/README/file-presence checks, an audience-specific target-fit card for professor/founder/maintainer outreach, and downloadable scorecard/target-fit/issue-draft/outreach-note/Markdown/CSV/JSON results, so the browser demo is useful for sharing as well as exploration.

The demo includes a one-click sample repo snapshot, a public GitHub URL box, and shareable prefilled links such as demo.html?repo=owner/repo or demo.html?repo=owner/repo&audience=professor. Browser GitHub audits stay bounded and prioritize README/manifests, CI, Docker/Make files, notebooks, and Python source, so a visitor can see multi-file findings immediately without preparing an upload. Use labcheck demo-link https://github.com/owner/repo to generate a safe prefilled URL from the CLI, add --audience professor to preselect the target-fit card, or add --format markdown --auto-audit for a paste-ready email, issue, README, or launch-post link.

Use it in CI

The GitHub Action runs the same deterministic audit without secrets, writes a compact scorecard plus the Markdown report into the job summary, emits SARIF for GitHub code-scanning integrations, exposes score outputs for PR summaries or sticky comments, and can produce a static SVG score badge plus a maintainer-friendly issue draft. Start with a soft report artifact, then commit a baseline and turn on fail-on: high when the repo is ready for a reproducibility gate.

labcheck init . labcheck init . --policy - uses: actions/checkout@v4 - uses: ThomasAquinas14/labcheck@v1 with: target: "." config-path: .labcheck.toml baseline-path: .labcheck-baseline.json report-path: labcheck-report.md json-path: labcheck-report.json sarif-path: labcheck-report.sarif badge-path: labcheck-badge.svg scorecard-path: labcheck-scorecard.md target-fit-path: labcheck-target-fit.md issue-draft-path: labcheck-issue-draft.md max-findings: "100" fail-on: high min-score: "80"

Prove cleanup progress

After a team fixes findings, labcheck compare turns two JSON reports into a before/after note with score deltas, severity deltas, resolved findings, and new findings. That makes cleanup progress easy to paste into a PR, lab handoff update, release note, or founder diligence follow-up.

labcheck scan . --format json --output before-labcheck-report.json # make fixes labcheck scan . --format json --output after-labcheck-report.json labcheck compare before-labcheck-report.json after-labcheck-report.json --output labcheck-compare.md

Self-explaining checks

The CLI includes a built-in check catalog, so someone who receives a report can run labcheck explain LC005 and immediately see what the finding means, why it matters, and what to fix.

labcheck checks labcheck explain LC005

Use it for outreach

`labcheck` is meant to be easy to share with professors, lab managers, maintainers, and ML/data founders. Use labcheck target-fit as a private go/no-go card before cold outreach, labcheck scorecard for a one-screen summary, labcheck issue for a respectful maintainer issue draft, labcheck outreach --audience professor or --audience founder for targeted notes that include a bounded browser-demo link on public GitHub targets, then labcheck pack --zip to generate a complete audit folder and a single archive with MANIFEST.md, machine-readable artifacts, and the full evidence trail.

labcheck demo-link https://github.com/owner/repo --audience professor --output labcheck-demo-link.txt labcheck demo-link https://github.com/owner/repo --format markdown --auto-audit --audience professor --output labcheck-demo-link.md labcheck target-fit https://github.com/owner/repo --audience professor --output labcheck-target-fit.md labcheck scorecard https://github.com/owner/repo --output labcheck-scorecard.md labcheck outreach https://github.com/owner/repo --output labcheck-outreach-note.md labcheck outreach https://github.com/owner/repo --audience founder --output labcheck-founder-note.md labcheck issue https://github.com/owner/repo --output labcheck-issue-draft.md labcheck pack https://github.com/owner/repo --output-dir labcheck-audit --zip
